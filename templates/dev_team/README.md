# Команда разработки — опциональный шаблон

Платформа Ai_RE_Project по умолчанию ведёт **только аналитику** (главы BABOK 3–7). Если вы ведёте
и разработку продукта с агентами, подключите команду: пять агентов, общие правила и скилл
проектирования интерфейса. Без этого шага ничего не меняется.

| Агент | Что делает | Пишет только в |
|---|---|---|
| `arch` | архитектура, ADR, декомпозиция функции на задачи, план | `architecture/`, блок «Архитектурное решение» страниц компонентов |
| `ux` | 2–3 варианта интерфейса, согласование, `decision.md` | `design/` |
| `dev` | код и unit-тесты по задаче и утверждённому дизайну | код продукта |
| `qa` | тест-план, тесты, поиск багов, приёмка UI | тесты, `qa/` |
| `devops` | сборка, окружения, секреты, деплой, бэкапы | compose, Dockerfile, `infra/`, `scripts/`, CI |

Цепочка: **Аналитик → Arch → UX → [апрув владельца] → Dev → QA**; DevOps — по задачам окружения.
Вход для Arch — карточка бизнес-функции `planned` и утверждённые требования
(`product_docs/README.md`); без неё Arch возвращает задачу аналитику. Один писатель на область.

## Подключение

```bash
python init_dev_team.py --project-id <project_id> --title "Название продукта" \
    --owner "Имя владельца" --tracker Linear --task-prefix "Pre." \
    --backend-dir backend/app/ --frontend-dir frontend/src/ --tests-dir backend/tests/
```

Скрипт рендерит `templates/dev_team/` в `.claude/agents/`, `.claude/rules/` и
`.claude/skills/ux_design/`, подставляя значения проекта (существующие файлы не перезаписывает,
`--dry-run` показывает результат заранее). Дальше перезапустите сессию (`/exit`, затем
`claude --continue`): новые файлы агентов подхватываются только после перезапуска.

Параметры: `--tracker-mcp` — имя MCP-сервера вашего трекера, чтобы агенты могли читать и
обновлять задачи (иначе они работают без доступа к трекеру); `--roles arch,dev,qa,devops` —
подключить не все роли (например, `ux` не нужен продукту без интерфейса; тогда не создаются агент
`ux` и скилл `ux_design`, а правило `ui_workflow.md` остаётся — на него ссылаются другие агенты).

## Что в шаблоне

```
templates/dev_team/
  agents/        arch.md, ux.md, dev.md, qa.md, devops.md      (с маркерами {{...}})
  rules/         dev_team.md (роли, цепочка, ворота, области записи), ui_workflow.md (согласование UI)
  skills/ux_design/SKILL.md
```

Файлы в шаблоне содержат маркеры `{{PROJECT_ID}}`, `{{OWNER}}`, `{{TRACKER}}` и т. п. **Не копируйте их
в `.claude/` вручную**: агент прочитал бы оставшийся маркер как инструкцию. Файлы в `.claude/`
после подключения принадлежат проекту — правьте их под свои процессы.

## Связь с документацией продукта

Агенты читают карточки БФ и страницы компонентов `product_docs/` как вход, но **не правят их**:
изменения поведения Dev, QA и DevOps описывают комментарием к задаче, а аналитик приводит
страницы к факту и запускает `python product_docs/check_product_docs.py`.
