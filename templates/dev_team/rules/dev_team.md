# Команда разработки проекта {{PROJECT_TITLE}}

Опциональный слой: агенты `arch`, `ux`, `dev`, `qa`, `devops` в `.claude/agents/` (установлен
`python init_dev_team.py`). Он не входит в четвёрку платформенных агентов
(`analyst`, `orchestrator`, `worker_llm`, `worker_file`) и не меняет их работу: без него платформа
ведёт только аналитику.

| Агент | Задачи в {{TASK_PREFIX}}… | Пишет только в |
|---|---|---|
| `arch` | `Arch-N` | `architecture/`; блок «Архитектурное решение» страниц компонентов; декомпозиция задач в {{TRACKER}} |
| `ux` | `UX-N` | `design/` |
| `dev` | `Dev-N` | `{{BACKEND_DIR}}`, `{{FRONTEND_DIR}}` |
| `qa` | `QA-N` | `{{TESTS_DIR}}`, `qa/` |
| `devops` | `DevOps-N` | compose-файлы, Dockerfile, `infra/`, `scripts/`, CI |
| аналитик (ведущая сессия) | `RE-N` | `output/` (через MCP-инструменты), `product_docs/` |

## Цепочка

```
Аналитик (требования, карточка БФ planned)
  → Arch (декомпозиция)
  → UX (варианты) → [апрув владельца]
  → Dev → QA
```

DevOps подключается по задачам окружения, сборки и деплоя. Задача с изменением интерфейса идёт
через `ux`; серверные и инфраструктурные задачи его пропускают. Ворота «Dev не стартует
UI-задачу без утверждённого `decision.md`» и порядок согласования — `.claude/rules/ui_workflow.md`.

## Ворота для Arch

Arch берёт функцию в работу только при карточке `product_docs/01_business_functions/BF-NN_*` в
статусе `planned` с разделом «Планируемое изменение», утверждённых требованиях (5.5) и сигнале
готовности аналитика в {{TRACKER}} («аналитика по BF-NN завершена»). Иначе возвращает задачу
аналитику с перечнем недостающего. Если архитектор — живой человек, правило то же.

## Один писатель на область

Параллельные задачи в одну область не заводятся: файлы пишет только владелец области (таблица
выше). Агент сообщает, если смежная задача в работе. Пробел или противоречие в требованиях
исполнитель не правит сам — заводит Issue или CR (5.4) аналитику.

## Документация после реализации

Dev, QA и DevOps **не правят** карточки БФ и страницы компонентов: изменение поведения,
контракта, модели данных или окружения они описывают комментарием к задаче. Аналитик приводит
страницы к факту (`implemented`) и запускает `python product_docs/check_product_docs.py` —
Definition of Done слоя документации (`product_docs/README.md`).

## Границы

- Требований агенты не придумывают и не меняют: владелец спецификации — аналитик.
- Решения, меняющие скоуп или срок, — рекомендация; финал за {{OWNER}}.
- Коммиты и пуш — только по просьбе пользователя.
- Предупреждай, не блокируй: нехватку данных называй и продолжай с допущением.
- Файлы агентов — плоский Markdown без маркеров шаблонизатора; изменённые файлы агентов
  подхватываются только после перезапуска сессии (`/exit`, затем `claude --continue`).
